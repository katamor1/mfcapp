# ADR 0008: Pin the application to C++17

- **Status:** Accepted
- **Date:** 2026-07-24
- **Decision owner:** Product owner instruction
- **Related design:** `docs/superpowers/specs/2026-07-23-shelf-manager-architecture-design.md`
- **Related plan:** `docs/superpowers/plans/2026-07-23-shelf-manager-mvp-foundation-fake-vertical-slice.md`

## Context

The target deployment and integration environment requires the entire application, including tests and adapters, to remain compatible with C++17. The initial implementation used several C++20 library and language features even though they were not essential to the architecture.

The functional requirements remain unchanged: the GUI monitors and operates workpieces, and external machine access remains behind Application ports. The language-version restriction is therefore an implementation constraint rather than an architectural change.

## Decision

1. Compile every project with `/std:c++17`.
2. Enable `/Zc:__cplusplus` so compile-time language checks report the selected standard accurately under MSVC.
3. Keep a compile-time regression assertion in every test executable through the shared bootstrap test.
4. Replace C++20 defaulted comparisons and the three-way comparison operator with explicit C++17 comparison operators.
5. Replace `std::jthread` and `std::stop_token` with `std::thread` plus an atomic stop flag and explicit join.
6. Replace `std::atomic<std::shared_ptr<T>>` with the C++17 atomic free functions for `std::shared_ptr<T>`.
7. Do not compile selected files as C++20 exceptions. The C++17 requirement applies to Domain, Application, Infrastructure, Presentation, MFC, and test projects uniformly.
8. New code and future COM adapter work must remain C++17-compatible unless this ADR is superseded by a later approved decision.

## Alternatives

### Keep C++20 and rely on the newest Visual C++ runtime

Rejected because it does not satisfy the deployment constraint.

### Compile only the MFC executable as C++17

Rejected because static libraries and tests could still introduce C++20 ABI, compiler, or maintenance dependencies.

### Compile a few source files as C++20

Rejected because a mixed language-level build would make the restriction difficult to verify and would preserve hidden migration risk.

## Consequences

### Positive

- The supported compiler contract is explicit and continuously verified.
- The CSV mock and future COM gateway remain replaceable through the existing interfaces.
- C++20-only dependencies cannot enter unnoticed through a single project.

### Negative

- Some comparison operators require explicit boilerplate.
- Thread cancellation and atomic snapshot publication require C++17-compatible implementation code rather than newer standard-library wrappers.

## Verification

- `Directory.Build.props` selects `stdcpp17` and `/Zc:__cplusplus`.
- `BuildBootstrapTests.cpp` fails compilation unless the selected language level is exactly C++17.
- GitHub Actions builds and runs tests in Debug/Release × Win32/x64.
- Source review checks for accidental use of `<=>`, `std::jthread`, `std::stop_token`, and `std::atomic<std::shared_ptr<...>>`.
